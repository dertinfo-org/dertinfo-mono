# App upgraded from Angular 20 to Angular 21

## Summary of the work completed

The app (`apps/dert-app`) now builds and runs on Angular **21.2.26**, CLI **21.2.30**, and TypeScript **5.9.3**. Ionic moved from **8.8.19** to **9.0.11**. RxJS stays **7.8.2**. `zone.js` stays **0.15.1**. Node stays **20.20.2**. `npm install` in `apps/dert-app/src/client` succeeds without `force`. `npm run build:hosted` succeeds. The app smoke suite passed.

Ionic moved first, while the app was still on Angular 20.3.35. That production build and the smoke suite passed before `ng update`. `IonicModule` is imported from `@ionic/angular/lazy`, and `provideIonicAngular()` is registered beside `IonicModule.forRoot()`.

The optional `use-application-builder` and `router-current-navigation` migrations were not run. The webpack `browser` builder stayed. `*ngIf` and `*ngFor` stayed. `APP_INITIALIZER` stayed. The `standalone: false` flags stayed. A required bootstrap migration added `provideZoneChangeDetection()` on `bootstrapModule`. A required CLI migration removed the `tsconfig.json` `lib` array. The control-flow migration rewrote 11 templates. Those edits were restored. The Protractor builder is still in the CLI package, so the `e2e` target stayed. `target` stayed `es2020`. Auth0 login was not rewritten.

This hop is branched from `feature/app-angular-20`. Notes are in [Upgrading Angular](../../technical/guides/upgrading-angular.md).

## Why the work was completed

This is the eighth hop from Angular 13 toward the website's Angular 22. Ionic 8's support ceiling is Angular 20. Ionic **9.0.11** peers Angular `>=18`, so it could move before the framework. Angular 21 still runs on Node 20, so there was no engine change before `ng update`. TypeScript **5.8.3** was below the Angular 21 floor. `ng update` moved it to **5.9.3**.

`provideZoneChangeDetection()` keeps today's Zone behaviour. It is not a move to zoneless. The control-flow rewrite was restored so the structural directives stay.

## Issues that were encountered on the way

- `@ionic/angular` **9.0.11** no longer exports `IonicModule` from the package root. The class is still exported from `@ionic/angular/lazy`, and it is deprecated. The nine NgModules import it from there. `IonicModule.forRoot()` stayed.
- The first smoke run after that import change uploaded a marking sheet (`201` from `api/dance/2108/markingsheet`) and then failed to render it. `PhotoWidget` injects `ModalController` from `@ionic/angular`, and the lazy module does not provide that token. The constructor error was `NG0201`, followed by an `NgForOf` assertion while the new sheet was inserted. `provideIonicAngular()` supplies `ModalController`. The production build and the smoke suite then passed on Angular 20.3.35, before `ng update`.
- `ng update @angular/cli@^21 @angular/core@^21` completed with `--allow-dirty` and no `--force`. CLI **21.2.30**, framework **21.2.26**. TypeScript moved from **5.8.3** to **5.9.3**. `zone.js` stayed **0.15.1**.
- The control-flow migration is no longer optional. It rewrote 11 templates. Those files were restored, so `*ngIf` and `*ngFor` stayed.
- The bootstrap migration added `provideZoneChangeDetection()` as `applicationProviders` on `platformBrowserDynamic().bootstrapModule` in `main.ts`.
- The CLI migration removed `lib` (`es2018` and `dom`) from `tsconfig.json`. `target` stayed `es2020`. `moduleResolution` stayed `bundler`.
- `npm install` warned that optional peer `karma` `^6.4.0` from `@angular/build` was overridden by the installed `karma` 6.3. The install did not fail. Karma stayed at **6.3.16**.
- The production build warns that Sass `@import` is deprecated. The styles were not rewritten.
- The initial bundle is **2.57 MB**. The 2 MB warning budget is exceeded by about 570 kB. The build exits 0.
- The Protractor builder is still present under `@angular-devkit/build-angular`, so it was not removed from `angular.json`.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 21.2 supports Node `^20.19.0 || ^22.12.0 || ^24.0.0`, TypeScript `>=5.9.0 <6.0.0`, and RxJS `^6.5.3 || ^7.4.0`. The installed CLI engines field is `^20.19.0 || ^22.12.0 || >=24.0.0`.
- [Angular v21](https://github.com/angular/angular/releases/tag/21.0.0) — Zone change detection is no longer scheduled unless `provideZoneChangeDetection` is provided. `ng update` adds that provider.
- [Ionic Angular build options](https://ionicframework.com/docs/angular/build-options) — `IonicModule` is deprecated. `provideIonicAngular()` supplies the controllers. The lazy module still declares the components for an NgModule app.
- [Ionic support policy](https://ionicframework.com/docs/reference/support) — Ionic 8 supports Angular through 20. This hop moved to Ionic 9.
- [Migrating to the new build system](https://angular.dev/tools/cli/build-system-migration) — the application builder migration is still optional. This hop kept the webpack `browser` builder.
- [Upgrading Angular](../../technical/guides/upgrading-angular.md) — the website restored the control-flow migration on this same hop and kept `provideZoneChangeDetection()`.
