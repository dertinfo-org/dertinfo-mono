# App upgraded from Angular 13 to Angular 14

## Summary of the work completed

The app (`apps/dert-app`) now builds and runs on Angular **14.3.0**, CLI **14.2.13**, and TypeScript **4.8.4**. Ionic stays on 6, at **6.1.15**. `npm install` in `apps/dert-app/src/client` succeeds on Node 16.20.2 without `force` and without peer errors. `npm run build:hosted` succeeds. The app smoke suite passed.

`ng update` removed `entryComponents` from `AppModule` and rewrote the dance score form and the range validator to `UntypedFormGroup` and `UntypedFormControl`. `tsconfig.json` `target` moved from `es2015` to `es2020`. `defaultProject` was removed from `angular.json`. The webpack `browser` builder stayed. Auth0 login was not rewritten.

The app dev server runs on portable Node **16.20.2**. The Static Web Apps proxy on port 44300 stayed on Node 24. App CI and the app image stay on Node 16. Notes for this hop are in [Upgrading Angular](../../technical/guides/upgrading-angular.md).

Pull request: https://github.com/dertinfo-org/dertinfo-mono/pull/153

## Why the work was completed

The website is on Angular 22. The app was on Angular 13, so the two clients could not share packages or the same Auth0 Angular login. This is the first hop. One major, a healthy dependency tree, and the smallest application change that still installs, builds, and passes the app smoke suite.

Ionic **6.0.7** publishes an open Angular peer, but the Ionic support policy starts Angular 14 at **6.1.9**. The app moved to the last 6.1 patch before `ng update`.

## Issues that were encountered on the way

- This machine's PATH is Node 24.19.0. The Angular 14 CLI does not run there. Update, install, `ng build`, and `ng serve` used portable Node **16.20.2**. A smoke run from that same shell failed because Playwright requires Node 18 or newer. The suite was run again on Node 24.19.0.
- `ng update @angular/cli@^14 @angular/core@^14` completed with `--allow-dirty` and no `--force`. A later `npm install` warned that transitive `node-releases` 2.0.64 wants Node `>=18`. That is an engine warning, not a peer error.
- The production build warns that `src/global.scss` imports `~swiper/scss` and `~@ionic/angular/css/ionic-swiper`. The build still completes. `ngcc` still processes `@ionic/storage-angular` and `@auth0/angular-jwt`.
- Ionic 6.1 renders `ion-segment-button` so the host intercepts clicks on the inner tab. The smoke page object now clicks the host. The Scores tab was already selected when that click timed out.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 14.2 and 14.3 support Node `^14.15.0 || ^16.10.0`, TypeScript `>=4.6.2 <4.9.0`, and RxJS `^6.5.3 || ^7.4.0`.
- [`ng update`](https://angular.dev/cli/update) — one major, latest patch of that major.
- [Ionic support policy](https://ionicframework.com/docs/reference/support) — Angular 14 support starts at Ionic 6.1.9.
- [Upgrading Angular](../../technical/guides/upgrading-angular.md) — the website hop method, now with the app watch-list for this step.

## Any remaining issues that we may wish to address

- The next hop is Angular 15. Ionic 6 can stay, at **6.3.6** or later. Node stays 16. The `~` stylesheet imports have to be checked again, because the website's Angular 15 builder stopped resolving them.
- `@ionic/storage-angular` and `@auth0/angular-jwt` are still View Engine. Angular 16 removes `ngcc`.
- The Dockerfile still runs `npm install --force`. The app install on the host no longer needs it.
- `node-releases` 2.0.64 wants Node `>=18`. App CI stays on Node 16 until the Angular 17 hop.
- Auth0 login is still `auth0-js` and `@auth0/angular-jwt`. Sharing that login with the website is later work.
- The full app upgrade is still [issue 123](https://github.com/dertinfo/dertinfo-mono/issues/123). This hop does not close it.
