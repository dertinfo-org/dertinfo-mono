# App upgraded from Angular 21 to Angular 22

## Summary of the work completed

The app (`apps/dert-app`) now builds and runs on Angular **22.2.1**, CLI **22.2.1**, and TypeScript **6.0.3**. That is the same Angular release as the website. Ionic stays **9.0.11**. RxJS stays **7.8.2**. `zone.js` stays **0.15.1**. Node moved from **20.20.2** to **22.23.3**. `npm install` in `apps/dert-app/src/client` succeeds without `force`. `npm run build:hosted` succeeds. The app smoke suite passed.

One stop was cleared while the app was still on Angular 21.2.26. App CI and the app Docker image moved from Node 20 to Node 22. Node 22.23.3 is inside both the Angular 21 range (`^22.12.0`) and the Angular 22 range (`^22.22.3`). The production build hash matched the Node 20 build, and the smoke suite passed, before `ng update`.

The optional application-builder and Karma-to-Vitest migrations were not run. The webpack `browser` builder stayed. `*ngIf` and `*ngFor` stayed. `APP_INITIALIZER` stayed. The `standalone: false` flags stayed. `provideZoneChangeDetection()` stayed. A required migration added `ChangeDetectionStrategy.Eager` on 19 components and `withXhr()` on `provideHttpClient`. `RouterModule.forRoot` sets `paramsInheritanceStrategy: 'emptyOnly'`. `tsconfig.json` sets `strict: false`, `esModuleInterop: false`, and `ignoreDeprecations: "6.0"`. `target` stayed `es2020`. The Protractor builder is no longer in the CLI package, so the `e2e` target was removed. Auth0 login was not rewritten.

This hop is branched from `feature/app-angular-21`. Notes are in [Upgrading Angular](../../technical/guides/upgrading-angular.md).

Pull request: https://github.com/dertinfo-org/dertinfo-mono/pull/162

## Why the work was completed

This is the last hop from Angular 13 to the website's Angular 22.2.1. Angular 22 does not run on Node 20. Node 22 is still inside the Angular 21 range, so the app moved to Node 22 before the framework moved. TypeScript **5.9.3** was below the Angular 22 floor. `ng update` moved it to **6.0.3**.

`ChangeDetectionStrategy.Eager`, `withXhr()`, and `paramsInheritanceStrategy: 'emptyOnly'` keep today's change detection, XHR, and route-param behaviour. They are not a move to OnPush, Fetch, or the new router default.

## Issues that were encountered on the way

- App CI (`app-src-ci.yml`, `app-src-cd.yml`) and the app image moved to Node 22 while the app was still on Angular 21.2.26. `npm install` on Node **22.23.3** (npm 10.9.9) left `lockfileVersion` 3. The production build hash matched the Angular 21 build from Node 20 (`64549b3ec703b6a0`).
- `ng update @angular/cli@22.2.1 @angular/core@22.2.1` completed with `--allow-dirty` and no `--force`. The ranges it wrote then resolved to framework **22.2.6** and CLI **22.2.7**. `package.json` was set to exact **22.2.1** for `@angular/*`, the CLI, and `@angular-devkit/build-angular`, and TypeScript to **6.0.3**. Replacing the lockfile in place failed peer resolution, so `node_modules` and `package-lock.json` were recreated. The clean `npm install` succeeded with no `--force`. It printed one peer-override warning and did not fail.
- The core migration added `changeDetection: ChangeDetectionStrategy.Eager` on 19 components. It added `withXhr()` to `provideHttpClient(withInterceptorsFromDi())`. The `$safeNavigationMigration` migration made no changes. `provideZoneChangeDetection()` stayed on `bootstrapModule`.
- `paramsInheritanceStrategy` defaults to `'always'` and has no migration. `RouterModule.forRoot` now sets `paramsInheritanceStrategy: 'emptyOnly'`.
- TypeScript 6 defaults `strict` and `esModuleInterop` to true, and it errors on deprecated `baseUrl` and `downlevelIteration` unless `ignoreDeprecations` is `"6.0"`. `tsconfig.json` sets `strict: false`, `esModuleInterop: false`, and `ignoreDeprecations: "6.0"`. `target` stayed `es2020`. `strictTemplates` stayed true. The migration suppressed `nullishCoalescingNotNullable` and `optionalChainNotNullable` in `tsconfig.app.json` and `tsconfig.spec.json`. The production build accepted that combination.
- The Protractor builder is not in `@angular-devkit/build-angular` 22.2.1. The `e2e` target was removed from `angular.json`. The `protractor` package is still listed.
- The production build warns that `@angular-devkit/build-angular:browser` is deprecated with Webpack. It also warns that Sass `@import` is deprecated. The styles were not rewritten. The webpack builder stayed.
- The initial bundle is **2.70 MB**. The 2 MB warning budget is exceeded by about 701 kB. The build exits 0.
- Karma stayed **6.3.16**. `@angular/build` 22.2.1 still lists optional peer `karma` `^6.4.0`.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 22.2 supports Node `^22.22.3 || ^24.15.0 || ^26.0.0`, TypeScript `>=6.0.0 <6.1.0`, and RxJS `^6.5.3 || ^7.4.0`. The installed CLI 22.2.1 engines field is `^22.22.3 || ^24.15.0 || >=26.0.0`.
- [Angular v22](https://github.com/angular/angular/releases/tag/v22.0.0) — components without a strategy default to OnPush, and the old `Default` strategy is renamed `Eager`. HttpClient defaults to Fetch. `ng update` adds `Eager` and `withXhr()`.
- [Migrating to the new build system](https://angular.dev/tools/cli/build-system-migration) — the application builder migration is still optional. This hop kept the webpack `browser` builder. The production build prints that Webpack support is deprecated.
- [Upgrading Angular](../../technical/guides/upgrading-angular.md) — the website pinned this same 22.2.1 release, kept Eager change detection and `withXhr()`, and set `paramsInheritanceStrategy: 'emptyOnly'`.

## Any remaining issues that we may wish to address

- The app and the website are both on Angular **22.2.1**. The full app upgrade is still [issue 123](https://github.com/dertinfo/dertinfo-mono/issues/123). This hop does not close it.
- The webpack `browser` builder is deprecated. The application builder was not adopted.
- `IonicModule` is deprecated and imported from `@ionic/angular/lazy`. The NgModules stay.
- `*ngIf` and `*ngFor` are deprecated and still compile. The control-flow migration was not offered on this hop.
- Karma **6.3.16** is below the optional `@angular/build` peer `^6.4.0`. The unit-test script is not the check for this hop.
- The `protractor` package is still installed. The CLI builder and the `e2e` target are gone. The Playwright suite is the check that matters.
- The Dockerfile still runs `npm install --force`. The app install on the host does not need it.
- Auth0 login is still `auth0-js` and `@auth0/angular-jwt`. Sharing that login with the website is later work.
