# App upgraded from Angular 17 to Angular 18

## Summary of the work completed

The app (`apps/dert-app`) now builds and runs on Angular **18.2.14**, CLI **18.2.21**, and TypeScript **5.4.5**. Ionic moved from **7.8.6** to **8.8.19**. RxJS stays **7.8.2**. `zone.js` stays **0.14.10**. Node stays **18.20.8**. `npm install` in `apps/dert-app/src/client` succeeds without `force` and without peer errors. `npm run build:hosted` succeeds. The app smoke suite passed.

Ionic moved first, while the app was still on Angular 17.3.12. That production build succeeded before `ng update`. The optional `use-application-builder` migration was not run. The webpack `browser` builder stayed. The core migration replaced `HttpClientModule` with `provideHttpClient(withInterceptorsFromDi())`. The Protractor builder is still in the CLI package, so the `e2e` target stayed. `target` stayed `es2020`. Auth0 login was not rewritten.

This hop is branched from `feature/app-angular-17`. Notes are in [Upgrading Angular](../../technical/guides/upgrading-angular.md).

Pull request: https://github.com/dertinfo-org/dertinfo-mono/pull/157

## Why the work was completed

This is the fifth hop from Angular 13 toward the website's Angular 22. Ionic 7's support ceiling is Angular 17. Ionic 8 supports Angular 18 from **8.2.0**, and **8.8.19** is the latest 8.x. Its peer range is Angular `>=16`, so the same release can stay in place for the Angular 19 and 20 hops unless a peer or the build refuses it.

## Issues that were encountered on the way

- `ng update @angular/cli@^18 @angular/core@^18` completed with `--allow-dirty` and no `--force`. It did not move TypeScript or `zone.js`. It listed `use-application-builder` and did not run it.
- The production build skips Ionic selectors that use `:host-context`, `:dir`, and `::part`. The build still completes.
- The initial bundle is **2.22 MB**. The 2 MB warning budget is exceeded by about 127 kB. The build exits 0.
- The Protractor builder is still present under `@angular-devkit/build-angular`, so it was not removed from `angular.json`.
- The dance list page has no selector, so its host is `ng-component`. After this hop that page stays `display: flex` underneath the dance detail. The detail page is on top and receives the clicks. The smoke helper now waits for the team heading inside `page-dance-detail`.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 18.2 supports Node `^18.19.1 || ^20.11.1 || ^22.0.0`, TypeScript `>=5.4.0 <5.6.0`, and RxJS `^6.5.3 || ^7.4.0`. The installed CLI engines field is `^18.19.1 || ^20.11.1 || >=22.0.0`.
- [Ionic support policy](https://ionicframework.com/docs/reference/support) — Ionic 8 supports Angular 16 through 20. Angular 18 support starts at Ionic 8.2.0.
- [Updating to Ionic 8](https://ionicframework.com/docs/updating/8-0) — the required code change in this app was none. `IonBackButtonDelegate` is not used.
- [Upgrading Angular](../../technical/guides/upgrading-angular.md) — the website kept the webpack builder on this hop and let the core migration replace `HttpClientModule`.

## Any remaining issues that we may wish to address

- The next hop is Angular 19. Ionic **8.8.19** peers Angular `>=16`. Stay on it unless a peer or the build refuses it. Node **18.20.8** is inside the Angular 19 range. TypeScript **5.4.5** is not. Angular 19 needs TypeScript `>=5.5.0`. Let `ng update` move it.
- The dance list page is still mounted under the dance detail. Giving that page a selector, or finding why Ionic no longer marks it `ion-page-hidden`, is separate from this hop.
- The Dockerfile still runs `npm install --force`. The app install on the host does not need it.
- The Protractor target is still configured. The Playwright suite is the check that matters.
- Auth0 login is still `auth0-js` and `@auth0/angular-jwt`. Sharing that login with the website is later work.
- The full app upgrade is still [issue 123](https://github.com/dertinfo/dertinfo-mono/issues/123). This hop does not close it.
