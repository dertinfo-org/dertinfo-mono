# App upgraded from Angular 14 to Angular 15

## Summary of the work completed

The app (`apps/dert-app`) now builds and runs on Angular **15.2.10**, CLI **15.2.11**, and TypeScript **4.8.4**. Ionic stays on 6, at **6.3.10**. `npm install` in `apps/dert-app/src/client` succeeds on Node 16.20.2 without `force` and without peer errors. `npm run build:hosted` succeeds. The app smoke suite passed.

`src/global.scss` no longer uses `~` imports. Ionic CSS is imported from `node_modules`. `swiper/scss` is imported by its package export. The schematic set `tsconfig.json` `target` to `ES2022` and added `useDefineForClassFields: false`. Those two edits were reverted, so the checked-in target stays `es2020`. `.browserslistrc` matched the CLI default and was removed. `src/test.ts` no longer loads specs with `require.context`. The webpack `browser` builder stayed. Auth0 login was not rewritten.

This hop is branched from `feature/app-angular-14`. Notes are in [Upgrading Angular](../../technical/guides/upgrading-angular.md).

Pull request: https://github.com/dertinfo-org/dertinfo-mono/pull/154

## Why the work was completed

This is the second hop from Angular 13 toward the website's Angular 22. The aim is the same as the first hop: one major, a healthy dependency tree, and the smallest application change that still installs, builds, and passes the app smoke suite.

Ionic **6.1.15** is below the Angular 15 support line. The [Ionic support policy](https://ionicframework.com/docs/reference/support) starts Angular 15 at Ionic **6.3.6**. The app moved to the last 6.3 patch before `ng update`.

## Issues that were encountered on the way

- `ng update @angular/cli@^15 @angular/core@^15` completed with `--allow-dirty` and no `--force`. A later `npm install` still warns that transitive `node-releases` 2.0.64 wants Node `>=18`. That is an engine warning, not a peer error.
- The production build failed on `@import "~swiper/scss"`. Sass on this CLI does not resolve the `~` prefix, and `@ionic/angular` does not export its CSS files. The Ionic imports are now relative paths under `node_modules`. `swiper/scss` is exported, so that import has no prefix.
- The CLI migration rewrote `target` and `useDefineForClassFields`. The production build still warns that the CLI applies ES2022 itself. The checked-in file stays `es2020`.
- `ngcc` still processes `@ionic/storage-angular` and `@auth0/angular-jwt`.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 15.2 supports Node `^14.20.0 || ^16.13.0 || ^18.10.0`, TypeScript `>=4.8.2 <5.0.0`, and RxJS `^6.5.3 || ^7.4.0`.
- [`ng update`](https://angular.dev/cli/update) — one major, latest patch of that major.
- [Ionic support policy](https://ionicframework.com/docs/reference/support) — Angular 15 support starts at Ionic 6.3.6.
- [Upgrading Angular](../../technical/guides/upgrading-angular.md) — the website kept `target` at `es2020` when the Angular 15 schematic wrote `ES2022`. This hop does the same.

## Any remaining issues that we may wish to address

- The next hop is Angular 16. Ionic 6 cannot peer that major, so the app moves to Ionic 7. Angular 16 removes `ngcc`, so `@ionic/storage-angular` and `@auth0/angular-jwt` have to be checked before `ng update`.
- The Dockerfile still runs `npm install --force`. The app install on the host does not need it.
- `node-releases` 2.0.64 wants Node `>=18`. App CI stays on Node 16 until the Angular 17 hop.
- Auth0 login is still `auth0-js` and `@auth0/angular-jwt`. Sharing that login with the website is later work.
- The full app upgrade is still [issue 123](https://github.com/dertinfo/dertinfo-mono/issues/123). This hop does not close it.
