# App upgraded from Angular 15 to Angular 16

## Summary of the work completed

The app (`apps/dert-app`) now builds and runs on Angular **16.2.12**, CLI **16.2.16**, and TypeScript **5.1.6**. Ionic is **7.8.6**. RxJS is **7.8.2**. `zone.js` is **0.13.3**. `npm install` in `apps/dert-app/src/client` succeeds on Node 16.20.2 without `force` and without peer errors. `npm run build:hosted` succeeds. The app smoke suite passed.

Before `ng update`, `@ionic/storage-angular` moved to **4.0.0** and `@auth0/angular-jwt` to **5.2.0**. Those releases publish `fesm2020`. Angular 16 removes `ngcc`. Five services replaced `Observable.throw` with `throwError(() => errMsg)`. `src/polyfills.ts` imports `zone.js`, and `src/test.ts` imports `zone.js/testing`. The guard migration removed `implements CanActivate` from `AuthGuard`. `canActivate` stayed. The Protractor builder is still in the CLI package, so the `e2e` target stayed. The webpack `browser` builder stayed. `target` stayed `es2020`. Auth0 login was not rewritten.

This hop is branched from `feature/app-angular-15`. Notes are in [Upgrading Angular](../../technical/guides/upgrading-angular.md).

Pull request: https://github.com/dertinfo-org/dertinfo-mono/pull/155

## Why the work was completed

This is the third hop from Angular 13 toward the website's Angular 22. Ionic 6 cannot support Angular 16. Ionic 7 can, and it requires RxJS 7. The View Engine builds of storage and angular-jwt would not survive the removal of `ngcc`. Those stops were cleared on Angular 15, then `ng update` moved the framework.

## Issues that were encountered on the way

- The first production build after RxJS 7 failed because `Observable.throw` is not on `Observable` in RxJS 7. Five `handleError` methods now return `throwError(() => errMsg)`. The Angular 15 production build then succeeded, before `ng update`.
- `ng update @angular/cli@^16 @angular/core@^16` completed with `--allow-dirty` and no `--force`. It moved TypeScript from **4.8.4** to **5.1.6** and `zone.js` from **0.11.4** to **0.13.3**.
- `zone.js` 0.13 does not ship `dist/zone`. The old polyfill and test imports were updated.
- A later `npm install` still warns that transitive `node-releases` 2.0.64 wants Node `>=18`. That is an engine warning, not a peer error.
- The production build skips Ionic selectors that use `:host-context`, `:dir`, and `::part`. The build still completes.
- The Protractor builder is still present under `@angular-devkit/build-angular`, so it was not removed from `angular.json`.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 16.2 supports Node `^16.14.0 || ^18.10.0`, TypeScript `>=4.9.3 <5.2.0`, and RxJS `^6.5.3 || ^7.4.0`.
- [Updating to Ionic 7](https://ionicframework.com/docs/updating/7-0) — Ionic 7 requires RxJS `>=7.5.0`.
- [Ionic support policy](https://ionicframework.com/docs/reference/support) — Ionic 7 supports Angular 14 through 17. Angular 17 support starts at Ionic 7.5.4. This hop installed **7.8.6**.
- [Upgrading Angular](../../technical/guides/upgrading-angular.md) — the website cleared View Engine packages before the Angular 16 hop. This hop does the same for storage and angular-jwt.

## Any remaining issues that we may wish to address

- The next hop is Angular 17. Node 16 is outside that range. Move app CI, the app image, and the portable Node to **18.20.8** while still on Angular 16, and re-run the smoke suite before `ng update`. Ionic **7.8.6** already covers Angular 17.
- The Dockerfile still runs `npm install --force`. The app install on the host does not need it.
- `node-releases` 2.0.64 wants Node `>=18`. That warning should go away when Node moves.
- The Protractor target is still configured. The Playwright suite is the check that matters.
- Auth0 login is still `auth0-js` and `@auth0/angular-jwt`. Sharing that login with the website is later work.
- The full app upgrade is still [issue 123](https://github.com/dertinfo/dertinfo-mono/issues/123). This hop does not close it.
