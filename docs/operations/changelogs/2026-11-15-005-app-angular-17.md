# App upgraded from Angular 16 to Angular 17

## Summary of the work completed

The app (`apps/dert-app`) now builds and runs on Angular **17.3.12**, CLI **17.3.17**, and TypeScript **5.4.5**. Ionic stays on 7, at **7.8.6**. RxJS stays **7.8.2**. `zone.js` is **0.14.10**. App CI, the app image, and local `ng` are Node **18.20.8**. `npm install` in `apps/dert-app/src/client` succeeds without `force` and without peer errors. `npm run build:hosted` succeeds. The app smoke suite passed.

Node moved first, while the app was still on Angular 16.2.12. That production build and the smoke suite passed before `ng update`. The schematic renamed `browserTarget` to `buildTarget` on the dev server and extract-i18n targets. The webpack `browser` builder stayed. The Protractor builder is still in the CLI package, so the `e2e` target stayed. `target` stayed `es2020`. Auth0 login was not rewritten.

This hop is branched from `feature/app-angular-16`. Notes are in [Upgrading Angular](../../technical/guides/upgrading-angular.md).

## Why the work was completed

This is the fourth hop from Angular 13 toward the website's Angular 22. Angular 17 does not run on Node 16. Node 18 is still inside the Angular 16 range, so the app moved to Node 18 before the framework moved. Ionic **7.8.6** already covers Angular 17, which starts at Ionic 7.5.4, so Ionic stayed.

## Issues that were encountered on the way

- `ng update @angular/cli@^17 @angular/core@^17` completed with `--allow-dirty` and no `--force`. It moved TypeScript from **5.1.6** to **5.4.5** and `zone.js` from **0.13.3** to **0.14.10**.
- The control-flow migration found no `@` in templates to escape.
- The production build skips Ionic selectors that use `:host-context`, `:dir`, and `::part`. The build still completes.
- The initial bundle is **2.16 MB**. The 2 MB warning budget is exceeded by about 162 kB. The build exits 0.
- The Protractor builder is still present under `@angular-devkit/build-angular`, so it was not removed from `angular.json`. The Cordova targets still say `browserTarget`.
- The `node-releases` engine warning from Node 16 did not appear on Node 18.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 17.3 supports Node `^18.13.0 || ^20.9.0`, TypeScript `>=5.2.0 <5.5.0`, and RxJS `^6.5.3 || ^7.4.0`. The installed CLI engines field is `^18.13.0 || >=20.9.0`.
- [Ionic support policy](https://ionicframework.com/docs/reference/support) — Ionic 7 supports Angular 14 through 17. Angular 17 support starts at Ionic 7.5.4. This hop stayed on **7.8.6**.
- [Upgrading Angular](../../technical/guides/upgrading-angular.md) — the website moved to Node 18 before `ng update` on this same hop, and kept the webpack builder.
